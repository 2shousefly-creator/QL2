# Shoulder-board material and export

`shoulder-twill.png` is an original cloth material generated with the built-in ImageGen tool. The final prompt is recorded in `scripts/uniforms/imagegen-prompts.json` under `shoulderBoardMaterial`. No garment sprite is regenerated by this workflow.

The 24 production PNGs are exported from this shared material and `scripts/uniforms/shoulder-board-spec.json`. All coordinates are in a 512 × 192 canvas: body bounds (24, 36)–(488, 156), square outer end on the left and clipped inner end on the right, gold attachment button at (452, 96), radius 12. The current React mirror places both the clipped end and button toward the collar on both shoulders. Only the body/trim contours are reflected in the exporter; marks, button, material and lighting retain their coordinates, so chevrons still point inward and bars stay near the outer end.

All regular stars share radius 34, inner ratio 0.44, 80 px center spacing and the same metal/facets. Their visible bounds are centered vertically. White stripes are 6 px thick with 14 px center spacing, clipped continuously to the cloth beneath the stars and button. Bars and chevrons use fixed geometry and spacing from the spec.

The base border is 8 px. Tổng Tư Lệnh uses 16 px (twice the previous approximately 8 px gold edge), an inset engraved line and one radius-42 star with brighter raised ridges. Both star sizes fit inside their borders; the central insignia field is centered at x=246, leaving room for the attachment button.

Re-export with Node.js and authoring dependency Sharp 0.35.4 (also used for rank badges):

```sh
NODE_PATH=/path/to/node_modules node scripts/uniforms/render-shoulder-boards.cjs
```

On PowerShell, set `NODE_PATH` to the Sharp package directory's parent and run `scripts/uniforms/export-sprites.ps1 -ShoulderBoardsOnly`. `-OutputRoot` remains supported. The manifest exporter now routes board entries through this same exporter, so independent image generations cannot introduce inconsistent symbol sizes. Generated PNGs retain RGBA transparency and existing filenames. SVG markup exists only inside the offline authoring script; the game consumes PNGs.
